# デプロイ用 SSH 鍵の入れ替え

GitHub Actions がお名前.com RS への接続に使っている SSH 鍵（クライアント鍵）を新しいものに入れ替える手順です。
初期設定の詳細は [deploy-01-ssh-setup.md](./deploy-01-ssh-setup.md) を参照してください。

## 2種類の鍵の違い

| 鍵 | 持ち主 | 登録場所 | このドキュメントの対象 |
|---|---|---|---|
| クライアント鍵（秘密鍵 / 公開鍵） | 自分（デプロイ専用） | 秘密鍵 → `SSH_PRIVATE_KEY`、公開鍵 → RS の SSH Key | ✅ |
| ホスト鍵（サーバーの公開鍵） | お名前.com のサーバー | `SSH_KNOWN_HOSTS` | ❌（[deploy-04-server-hostname-change.md](./deploy-04-server-hostname-change.md)） |

クライアント鍵を入れ替えても、`SSH_KNOWN_HOSTS` を変更する必要はありません。

## 入れ替えるタイミング

- **すぐに入れ替える**: 秘密鍵が漏えいした疑いがある、秘密鍵を保存していた PC を紛失・譲渡した、リポジトリの共同作業者が抜けた
- **定期的に入れ替える**: 年に1回程度を目安に（期限はないが、長く使うほど漏えいに気づかないリスクが増える）

## 通常の入れ替え手順

RS には複数の SSH Key を同時に登録できるので、**新しい鍵で動くことを確認してから古い鍵を止める** 順番で進めます。デプロイが止まる時間はありません。

### 1. 新しい鍵ペアを作る（手元の PC）

ファイル名に年などを付けて、古い鍵と区別します。

```powershell
ssh-keygen -t ed25519 -C "github-actions-deploy-2027" -f $HOME\.ssh\onamae_deploy_2027
```

パスフレーズは空のまま Enter を2回押します。

### 2. 新しい公開鍵を RS に登録する

1. コントロールパネル →「サーバー」→「SSH」→「+SSH Key を追加」。
2. 作成方法「インポート」を選び、Key名（例: `github-actions-2027`）と `onamae_deploy_2027.pub` の中身を貼り付けて登録する。
3. 新しい Key の「利用設定」が ON になっていることを確認する。

### 3. 手元で新しい鍵での接続を確認する

```powershell
ssh -i $HOME\.ssh\onamae_deploy_2027 -p <ポート番号> <ユーザー名>@<ホスト名>
```

ログインできれば OK です（`exit` で抜ける）。

### 4. GitHub の Secret を差し替える

Settings → Secrets and variables → Actions → `SSH_PRIVATE_KEY` の「Update」で、`onamae_deploy_2027`（秘密鍵）の中身すべてに置き換えます（BEGIN / END 行を含む）。

### 5. Actions で確認する

Actions タブから `master` を選んで手動実行（dry-run ON）し、`(DRY RUN)` で正常に終わることを確認します。手順は [deploy-02-github-actions.md の「dry-run で確認する」](./deploy-02-github-actions.md#dry-run-で確認する) を参照してください。

### 6. 古い鍵を止める

1. コントロールパネルの SSH Key 一覧で、**古い Key** の「利用設定」を OFF にする。
2. もう一度 Actions で dry-run を実行し、正常に終わることを確認する（新しい鍵だけで動いている証拠）。
3. 問題なければ、古い Key を一覧から削除する。
4. 手元の古い鍵ファイル（`onamae_deploy` / `onamae_deploy.pub`）を削除する。

## 漏えいが疑われるときの手順

漏えいの疑いがある場合は、**先に古い鍵を止めて** から入れ替えます。入れ替えが終わるまでの間、デプロイは失敗しますが、不正なアクセスを止めることを優先します。

1. コントロールパネルで古い Key の「利用設定」を **すぐに OFF** にする（この時点で、その鍵での接続はできなくなる）。
2. 上の「通常の入れ替え手順」の 1〜5 を行う。
3. 古い Key を削除する。
4. サーバー上のファイルが改ざんされていないか確認する（`ls -la ~/public_html/<ドメイン名>` で見覚えのないファイルがないか、サイトの表示に異常がないか）。気になる場合は、dry-run を外して手動実行し、`dist/` の内容でサーバーを上書きする。
